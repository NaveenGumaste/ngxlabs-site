# Favicon + Social Preview Banner Implementation Playbook

> **Audience:** an AI coding agent implementing the same end result in *any* project.
> **Source of truth:** this document was reverse-engineered from the live `ngxlabs-site` implementation (Next.js 16 App Router). Replicate the *outcomes* and *file contracts* below; adapt syntax to the target stack.
> **Success definition:** the site tab shows the brand mark; iOS “Add to Home Screen” uses the apple touch icon; PWA install uses 192/512 icons; pasting the production URL into WhatsApp / iMessage / Slack / Discord / Telegram / LinkedIn / X / Facebook shows a **large 1200×630 preview card** with the correct title, description, and banner image.

Do not improvise a 32×32-only favicon and call it done. WhatsApp and most chat apps **do not** use the favicon. They scrape Open Graph (`og:image`) and Twitter Card tags. Both systems must be implemented together.

---

## 0. What this repo actually does (mental model)

There are **three independent image systems**. All three are required.

| System | Purpose | Who consumes it | This repo’s primary files |
|---|---|---|---|
| **Favicon pack** | Browser tab, bookmarks, Google SERP sitelink icon | Browsers, crawlers | `public/favicon.ico`, `public/icon-*`, `public/apple-touch-icon.*`, `src/app/icon.tsx`, `src/app/layout.tsx` `icons` |
| **PWA / install icons** | “Add to Home Screen”, Android Chrome install | Chrome, Safari, Edge | `src/app/manifest.ts` → `/icon-192x192.*`, `/icon-512x512.*` |
| **Social preview banner (OG)** | Link unfurl thumbnail in WhatsApp, Slack, Discord, X, LinkedIn, iMessage, Telegram, Facebook | `facebookexternalhit`, `WhatsApp`, `Twitterbot`, `Slackbot`, `Discordbot`, `LinkedInBot`, `TelegramBot` | `public/og-image.png` (1200×630), `src/app/layout.tsx` `openGraph` + `twitter`, `src/app/opengraph-image.tsx`, `src/app/twitter-image.tsx` |

A single **master source PNG** (`public/vericon.png`, 500×500 RGBA) is the only artwork a human designs. Everything else is generated by `scripts/generate-favicons.mjs` via `sharp`.

```
public/vericon.png          ← YOU design this (square, transparent or solid, ≥512px)
        │
        ▼
scripts/generate-favicons.mjs   (bun run favicons)
        │
        ├── favicon.ico / .webp / .avif
        ├── vericon.webp / .avif
        ├── icon-{16,32,48,64,96,128,180,192,256,384,512}x{same}.{png,webp,avif}
        ├── apple-touch-icon.png / .webp
        └── og-image.png (1200×630) + og-image.webp
                │
                ▼
src/app/layout.tsx  metadata.icons + openGraph.images + twitter.images
src/app/manifest.ts icons
src/app/icon.tsx    Next.js App Router file convention → /icon
src/app/opengraph-image.tsx  convention → /opengraph-image
src/app/twitter-image.tsx    convention → /twitter-image
src/app/robots.ts   allow WhatsApp + facebookexternalhit + Twitterbot + …
```

## 1. Non-negotiable contracts (copy these numbers)

If you change these, WhatsApp / X / LinkedIn will silently fall back to a tiny icon or no image.

### 1.1 Master icon

| Property | Required value |
|---|---|
| Path | `public/vericon.png` (or rename consistently in the generator) |
| Shape | Square |
| Minimum size | **512×512**. This repo’s source is **500×500** RGBA; 512+ is safer. 1024×1024 is ideal. |
| Color type | PNG, 8-bit RGBA, transparency allowed |
| Content | Centered mark with **safe padding** (~10–15% inset). Tiny details vanish at 16×16. |
| Background | Transparent is fine for favicons. For OG, the generator composites the mark onto a designed 1200×630 canvas — do **not** use a transparent OG image. |

### 1.2 Favicon sizes this generator emits

`16, 32, 48, 64, 96, 128, 180, 192, 256, 384, 512` in **PNG + WebP + AVIF**.

Plus named aliases:

| File | Size | Why it exists |
|---|---|---|
| `favicon.ico` | 32×32 PNG bytes saved with `.ico` extension | Legacy `/favicon.ico` lookup. Modern browsers accept a PNG-in-ICO. |
| `favicon.webp` / `favicon.avif` | 512×512 | Modern `rel="icon"` |
| `apple-touch-icon.png` / `.webp` | 180×180 | iOS home screen. Apple specifically looks for `/apple-touch-icon.png`. |
| `vericon.webp` / `vericon.avif` | 512×512 | Compressed copies of the master |

Resize options used everywhere: `fit: "contain"` + transparent background `{ r:0, g:0, b:0, alpha:0 }`.

Quality settings used:

- WebP: `quality: 95, effort: 6`
- AVIF: `quality: 90, effort: 6`
- PNG icons: `compressionLevel: 9`
- OG PNG: `compressionLevel: 8`
- OG WebP: `quality: 92`

### 1.3 Open Graph / WhatsApp banner (the thing that makes chat previews work)

| Property | Required value | Why |
|---|---|---|
| File | `/og-image.png` served from the site origin | WhatsApp is pickiest about a **public, absolute, HTTPS** PNG |
| Dimensions | **exactly 1200×630** | Facebook/WhatsApp recommended OG size. Aspect ≈ 1.91:1. Other ratios get cropped or ignored. |
| Format | PNG (primary). WebP extra is optional. | WhatsApp historically mishandles WebP / AVIF / SVG for unfurls. **Always expose PNG in `og:image`.** |
| File size | Keep under ~1 MB. This repo’s PNG is ~458 KB; WebP ~74 KB. | WhatsApp may drop images that are too large or too slow. |
| Color | Opaque. Never transparent. | Transparent OG images render as black/white garbage in chat. |
| URL in HTML | **Absolute** `https://your-domain.tld/og-image.png` | Relative `/og-image.png` is the #1 reason WhatsApp shows no thumbnail. |
| `og:image:width` / `height` | `1200` / `630` | Helps crawlers skip a HEAD probe. |
| Twitter card | `summary_large_image` | Small `summary` card uses a square crop and looks like a favicon. |

### 1.4 HTML meta that WhatsApp actually reads

WhatsApp’s crawler (`WhatsApp` UA) is a Facebook-family scraper. It wants:

```html
<meta property="og:type" content="website" />
<meta property="og:url" content="https://your-domain.tld/" />
<meta property="og:title" content="…" />
<meta property="og:description" content="…" />
<meta property="og:image" content="https://your-domain.tld/og-image.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:alt" content="…" />
<meta property="og:site_name" content="…" />
<meta property="og:locale" content="en_IN" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://your-domain.tld/og-image.png" />
```

In Next.js these are **not** hand-written `<meta>` tags. They are produced by the `metadata` export + `metadataBase`. `metadataBase` is what turns `/og-image.png` into `https://ngxlabs.tech/og-image.png`.

## 3. Step-by-step implementation

Execute in this order. Do not wire metadata before the PNG files exist on disk.

### Step 1 — Design the master mark

1. Create a **square** logo/mark.
2. Export as PNG, RGBA, ≥512px (1024px preferred).
3. Save it at:

```
public/vericon.png
```

Rules for the artwork:

- High contrast against both light and dark tab bars (or provide a version that works on dark — this site’s chrome `themeColor` is `#06080F`).
- No tiny hairlines, no 8pt type inside the mark. At 16×16 only the silhouette survives.
- Keep the glyph inside a ~70–80% safe square so `fit: "contain"` plus browser rounding does not clip it.
- Do **not** put the wordmark-only lockup here if the wordmark is long; OG text is drawn separately in the generator.

### Step 2 — Drop in the generator script

Create `scripts/generate-favicons.mjs`. This is the exact pipeline used by this repo. Customize only the constants at the top and the OG SVG overlay copy/colors.

```js
import sharp from "sharp";
import fs from "fs";
import path from "path";

// ─── customize per project ───────────────────────────────────────────
const MASTER = "public/vericon.png";          // square source
const PUBLIC_DIR = "public";
const OG_NAME = "Naveen Gumaste";             // line 1 on the banner
const OG_SUB =
  "Frontend Developer & DevOps Engineer · ngxlabs.tech"; // line 2
const OG_BG = "#06080F";                      // must be opaque
const OG_GLOW_A = "#2563EB";
const OG_GLOW_B = "#DB2777";
const OG_TITLE_COLOR = "#FFFFFF";
const OG_SUB_COLOR = "#94A3B8";
// ─────────────────────────────────────────────────────────────────────

const inputPath = path.resolve(MASTER);
const publicDir = path.resolve(PUBLIC_DIR);

async function generateFavicons() {
  console.log(`Generating favicons + OG banner from ${MASTER}...`);

  if (!fs.existsSync(inputPath)) {
    throw new Error(`Master icon not found at ${inputPath}`);
  }

  const inputBuffer = fs.readFileSync(inputPath);
  const contain = {
    fit: "contain",
    background: { r: 0, g: 0, b: 0, alpha: 0 },
  };

  // 1. 512 master aliases
  await sharp(inputBuffer).resize(512, 512, contain).webp({ quality: 95, effort: 6 })
    .toFile(path.join(publicDir, "favicon.webp"));
  await sharp(inputBuffer).resize(512, 512, contain).avif({ quality: 90, effort: 6 })
    .toFile(path.join(publicDir, "favicon.avif"));
  await sharp(inputBuffer).resize(512, 512, contain).webp({ quality: 95, effort: 6 })
    .toFile(path.join(publicDir, "vericon.webp"));
  await sharp(inputBuffer).resize(512, 512, contain).avif({ quality: 90, effort: 6 })
    .toFile(path.join(publicDir, "vericon.avif"));

  // 2. Multi-resolution PNG / WebP / AVIF
  const sizes = [16, 32, 48, 64, 96, 128, 180, 192, 256, 384, 512];
  for (const size of sizes) {
    await sharp(inputBuffer).resize(size, size, contain).png({ compressionLevel: 9 })
      .toFile(path.join(publicDir, `icon-${size}x${size}.png`));
    await sharp(inputBuffer).resize(size, size, contain).webp({ quality: 95, effort: 6 })
      .toFile(path.join(publicDir, `icon-${size}x${size}.webp`));
    await sharp(inputBuffer).resize(size, size, contain).avif({ quality: 90, effort: 6 })
      .toFile(path.join(publicDir, `icon-${size}x${size}.avif`));
  }

  // 3. Apple touch icon (Safari looks for this exact filename)
  await sharp(inputBuffer).resize(180, 180, contain).png({ compressionLevel: 9 })
    .toFile(path.join(publicDir, "apple-touch-icon.png"));
  await sharp(inputBuffer).resize(180, 180, contain).webp({ quality: 95 })
    .toFile(path.join(publicDir, "apple-touch-icon.webp"));

  // 4. /favicon.ico — 32×32 PNG bytes with an .ico name.
  //    Modern + legacy browsers accept this. A real multi-size ICO is optional.
  await sharp(inputBuffer).resize(32, 32, contain).png()
    .toFile(path.join(publicDir, "favicon.ico"));

  // 5. 1200×630 OG / WhatsApp / Discord / Slack / X card
  //    Dark opaque canvas + radial glow + centered 440px mark + two text lines.
  const iconResized = await sharp(inputBuffer)
    .resize(440, 440, contain)
    .png()
    .toBuffer();

  const svgOverlay = `
    <svg width="1200" height="630" viewBox="0 0 1200 630" xmlns="http://www.w3.org/2000/svg">
      <defs>
        <radialGradient id="bgGlow" cx="50%" cy="50%" r="70%">
          <stop offset="0%" stop-color="${OG_GLOW_A}" stop-opacity="0.3"/>
          <stop offset="45%" stop-color="${OG_GLOW_B}" stop-opacity="0.25"/>
          <stop offset="100%" stop-color="${OG_BG}" stop-opacity="1"/>
        </radialGradient>
      </defs>
      <rect width="1200" height="630" fill="${OG_BG}"/>
      <rect width="1200" height="630" fill="url(#bgGlow)"/>
      <text x="600" y="520"
            font-family="system-ui, -apple-system, sans-serif"
            font-size="44" font-weight="bold"
            fill="${OG_TITLE_COLOR}" text-anchor="middle" letter-spacing="-1">${escapeXml(OG_NAME)}</text>
      <text x="600" y="565"
            font-family="system-ui, -apple-system, sans-serif"
            font-size="22" font-weight="500"
            fill="${OG_SUB_COLOR}" text-anchor="middle">${escapeXml(OG_SUB)}</text>
    </svg>
  `;

  await sharp(Buffer.from(svgOverlay))
    .composite([{ input: iconResized, top: 55, left: 380 }])
    .png({ compressionLevel: 8 })
    .toFile(path.join(publicDir, "og-image.png"));

  await sharp(path.join(publicDir, "og-image.png"))
    .webp({ quality: 92 })
    .toFile(path.join(publicDir, "og-image.webp"));

  console.log("Generated favicon pack + og-image.png / og-image.webp");
}

function escapeXml(s) {
  return String(s)
    .replaceAll("&", "&amp;")
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;");
}

generateFavicons().catch((err) => {
  console.error(err);
  process.exit(1);
});
```

**OG layout math (do not “eyeball” this):**

- Canvas: 1200×630
- Mark: 440×440, placed at `top: 55, left: 380` → horizontally centered (`(1200-440)/2 = 380`), sitting above the title
- Title baseline `y=520`, subtitle `y=565`
- Leave ≥48px padding from every edge; WhatsApp crops aggressively on some clients

If the target brand is light-mode, invert `OG_BG` / text colors. Never leave the canvas transparent.

### Step 4 — Centralize site identity

This repo keeps the canonical URL in `src/lib/site.ts`. You need a single source of truth because **absolute URLs** are what crawlers store.

```ts
// src/lib/site.ts  (minimum surface for icons/OG)
export const site = {
  name: "ngxlabs.tech",
  url: "https://ngxlabs.tech",          // no trailing slash
  locale: "en_IN",                      // og:locale
  description:
    "ngxlabs.tech is a Dharwad tech studio led by Naveen Gumaste. Frontend, full-stack, DevOps, and cloud work for startups that need to ship.",
  founder: { name: "Naveen Gumaste" },
} as const;
```

Rules:

- `site.url` must be the **production** origin (`https://…`), never `localhost`.
- Description length in this project is kept **100–160 characters** (see `tests/content.test.ts`). That range is also the practical OG/WhatsApp snippet window.
- `absUrl()` in `src/lib/utils.ts` hardcodes the same origin. If you copy it, keep it in sync with `site.url`.

```ts
export function absUrl(path = "/"): string {
  const base = "https://ngxlabs.tech";
  if (path === "/") return base;
  return `${base}${path.startsWith("/") ? path : `/${path}`}`;
}
```

### Step 5 — Wire Next.js Metadata (this is the WhatsApp fix)

In `src/app/layout.tsx` the critical pieces are:

1. `metadataBase: new URL(site.url)` — resolves every relative icon/OG path to an absolute URL.
2. `icons` — tab + apple touch.
3. `openGraph.images` pointing at **`/og-image.png`** with width/height.
4. `twitter.card: "summary_large_image"` and the same image.

Copy this shape. Replace strings, keep the image paths and sizes.

```ts
import type { Metadata, Viewport } from "next";
import { site } from "@/lib/site";

export const metadata: Metadata = {
  metadataBase: new URL(site.url), // REQUIRED. Without this, og:image is relative and WhatsApp fails.
  title: {
    default: "Naveen Gumaste | Frontend Developer & DevOps Engineer",
    template: `%s | ${site.name}`,
  },
  description: site.description,
  applicationName: site.name,
  authors: [{ name: site.founder.name, url: site.url }],
  creator: site.founder.name,
  publisher: site.name,
  alternates: { canonical: site.url },
  icons: {
    icon: [
      { url: "/favicon.ico", sizes: "any" },
      { url: "/icon-32x32.webp", sizes: "32x32", type: "image/webp" },
      { url: "/icon-16x16.webp", sizes: "16x16", type: "image/webp" },
      { url: "/icon-32x32.png", sizes: "32x32", type: "image/png" },
      { url: "/icon-16x16.png", sizes: "16x16", type: "image/png" },
      { url: "/favicon.webp", sizes: "512x512", type: "image/webp" },

    apple: [
      { url: "/apple-touch-icon.webp", sizes: "180x180", type: "image/webp" },
      { url: "/apple-touch-icon.png", sizes: "180x180", type: "image/png" },

      { rel: "icon", type: "image/avif", url: "/favicon.avif" },

      {
        url: "/og-image.png", // resolved against metadataBase → https://domain/og-image.png
        width: 1200,

  },

    card: "summary_large_image",
    creator: "@Z0D404",
    title: "Naveen Gumaste | Frontend Developer & DevOps Engineer",
    description: site.description,

  },

      index: true,

  themeColor: "#06080F",
  width: "device-width",
  initialScale: 1,

```

**Why `metadataBase` is the whole game for WhatsApp:**

Next.js serializes `images: [{ url: "/og-image.png" }]` into:

```
og:image = {metadataBase}/og-image.png
```

If `metadataBase` is missing, crawlers receive `/og-image.png` and most (WhatsApp especially) discard it. Never set `metadataBase` to `http://localhost:3000` in a production build.

Per-page helper in this repo (`src/lib/seo.ts`) sets title/description/canonical but **intentionally does not override `images`**, so every page inherits the root 1200×630 banner. If a page needs a unique card, add `openGraph.images` + `twitter.images` on that page’s `metadata` / `generateMetadata`.

```ts
// src/lib/seo.ts — inherit root OG image unless you pass one
export function pageMeta({ title, description, path, keywords, type = "website" }) {
  const url = absUrl(path);
  return {
    title,
    description,
    keywords,
    alternates: { canonical: url },
    openGraph: {
      title: `${title} | ${site.name}`,
      description,
      url,
      siteName: site.name,
      locale: site.locale,
      type,
      // do NOT omit images on purpose unless the root layout already provides them
    },
    twitter: {
      card: "summary_large_image",
      title: `${title} | ${site.name}`,
      description,
    },
  };
}
```

When porting: if a child `openGraph` object **replaces** the parent (Next.js shallow-merges some keys but replacing `openGraph` without `images` can drop the banner), **re-declare `images`** on every page that customizes OG.

### Step 6 — App Router file conventions (belt and suspenders)

These files give Next.js first-class `/icon`, `/opengraph-image`, and `/twitter-image` routes even if a crawler ignores `<link rel="icon">` / static `og:image`. Keep them.

#### `src/app/icon.tsx`

Serves `/icon` as a 32×32 PNG by embedding the already-generated `public/icon-32x32.png`. This avoids drawing the mark with Satori (which cannot load arbitrary local files the way you expect).

```tsx
import { ImageResponse } from "next/og";
import fs from "node:fs";
import path from "node:path";

export const size = { width: 32, height: 32 };
export const contentType = "image/png";

export default function Icon() {
  const iconPath = path.join(process.cwd(), "public/icon-32x32.png");
  const iconBase64 = fs.readFileSync(iconPath).toString("base64");
  const iconDataUrl = `data:image/png;base64,${iconBase64}`;

  return new ImageResponse(
    (
      <div
        style={{
          width: 32,
          height: 32,
          display: "flex",
          alignItems: "center",
          justifyContent: "center",
        }}
      >
        {/* eslint-disable-next-line @next/next/no-img-element */}
        <img
          src={iconDataUrl}
          width={32}
          height={32}
          alt="icon"
          style={{ width: 32, height: 32, objectFit: "contain" }}
        />
      </div>
    ),
    size,
  );
}
```

JSON-LD in this repo points `Organization.logo` at `absUrl("/icon")` (`src/lib/schema.ts`). That URL must keep working.

#### `src/app/opengraph-image.tsx`

Next.js will also emit `<meta property="og:image" content="https://domain/opengraph-image?...">` from this file. It is a **generated** 1200×630 PNG (Satori/ImageResponse), used as a fallback / alternate OG image.

```tsx
import { ImageResponse } from "next/og";

export const alt = "ngxlabs.tech - Bold Brands, resonate deep.";
export const size = { width: 1200, height: 630 };
export const contentType = "image/png";

export default function OpengraphImage() {
  return new ImageResponse(
    (
      <div
        style={{
          width: "100%",
          height: "100%",
          background: "#F5F0E8",
          color: "#141414",
          display: "flex",
          flexDirection: "column",
          justifyContent: "space-between",
          padding: 64,
          border: "16px solid #141414",
        }}
      >
        <div style={{ fontSize: 36, fontWeight: 700 }}>ngx</div>
        <div style={{ display: "flex", flexDirection: "column", gap: 16 }}>
          <div style={{ fontSize: 64, fontWeight: 800, lineHeight: 1.05, maxWidth: 900 }}>
```

**Which image does WhatsApp show?**

WhatsApp prefers the **first `og:image`**. Next.js may emit both:

- the static `/og-image.png` from `metadata.openGraph.images`
- the generated `/opengraph-image` from the file convention

Both must be valid 1200×630 PNGs served over HTTPS. If you want a single source of truth (recommended when porting), pick **one**:

- **Static-only (simplest, most reliable for WhatsApp):** keep `public/og-image.png` + metadata, delete `opengraph-image.tsx` / `twitter-image.tsx`.
- **Generated-only:** keep the `opengraph-image.tsx` convention and drop the static file from metadata.
- **This repo:** keeps both. The sharp-generated `og-image.png` is the designed WhatsApp banner (logo + name); the ImageResponse file is a typographic alternate.

When replicating “the thumbnail I see in WhatsApp” from this site, reproduce **`scripts/generate-favicons.mjs` step 5 + `metadata.openGraph.images → /og-image.png`**. That is the card that matches the logo.

Notes:

- `purpose: "maskable"` on the 512 PNG assumes the glyph has padding (safe zone). If the mark goes edge-to-edge, use `purpose: "any"` or provide a dedicated maskable asset with 20% padding.
- `theme_color` / `background_color` should match `viewport.themeColor`.

### Step 8 — Let the scrapers in (`robots.ts`)

A `Disallow: /` or a missing allow for social bots will produce “no preview” in WhatsApp even when the image is perfect.

This repo explicitly allows the bots that unfurl links:

```ts
import type { MetadataRoute } from "next";
import { absUrl } from "@/lib/utils";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: "*", allow: "/" },
      {
        userAgent: [
          "Googlebot",
          "Bingbot",
          "Applebot",
          "DuckDuckBot",
          "Baiduspider",
          "YandexBot",
          "Twitterbot",
          "facebookexternalhit",
          "LinkedInBot",
          "WhatsApp",
          "TelegramBot",
          "Discordbot",
          "Slackbot",
          "GPTBot",
          "ClaudeBot",
          "PerplexityBot",
        ],
        allow: "/",
      },
    ],
    sitemap: absUrl("/sitemap.xml"),
    host: "https://ngxlabs.tech",
  };
}
```

Also check, in any hosting/WAF/CDN:

- Do **not** challenge `facebookexternalhit` / `WhatsApp` with a JS captcha or bot fight.
- `og-image.png` must be world-readable (`Content-Type: image/png`, 200, no auth cookie).
- HTTPS with a valid cert. WhatsApp will not unfurl plain HTTP on modern clients.

## 5. Verification checklist (do not skip)

Run these against the **production** origin after deploy. Localhost previews are useless for WhatsApp.

### 5.1 Files exist and are the right pixels

```bash
curl -sI https://YOUR-DOMAIN/og-image.png | grep -Ei 'HTTP|content-type|content-length'
# HTTP/2 200
# content-type: image/png

curl -sI https://YOUR-DOMAIN/favicon.ico | grep -Ei 'HTTP|content-type'
curl -sI https://YOUR-DOMAIN/apple-touch-icon.png | grep -Ei 'HTTP|content-type'
```

`og-image.png` must be `image/png`, 200, publicly cacheable.

### 5.2 Rendered HTML contains absolute OG tags

```bash
curl -sL https://YOUR-DOMAIN/ | grep -iE 'og:image|og:title|twitter:card|rel="icon"'
```

You must see a full `https://YOUR-DOMAIN/og-image.png` (or `/opengraph-image`). If you see `/og-image.png` without a host, `metadataBase` is missing.

### 5.3 Debuggers (these are the real QA tools)

| Platform | Tool | What to look for |
|---|---|---|
| Facebook / WhatsApp / Instagram | https://developers.facebook.com/tools/debug/ | “Scrape Again”, confirm 1200×630 image, no warnings |
| X / Twitter | https://cards-dev.twitter.com/validator (or the post composer preview) | `summary_large_image`, full-width banner |
| LinkedIn | https://www.linkedin.com/post-inspector/ | Large image, not the favicon |
| Slack | Paste into a DM with yourself | Unfurl shows banner |
| Discord | Paste into a server | Embed image |
| Telegram | `@webpagebot` or paste in Saved Messages | Photo preview |
| WhatsApp | Paste the URL in a chat **with yourself**, wait 2–5s | Large thumbnail, title, description |

WhatsApp caches aggressively (often 24h+, sometimes keyed by exact URL). After changing `og-image.png`:

1. Run Facebook Sharing Debugger → **Scrape Again** (WhatsApp uses this cache).
2. Change the query string once if needed: `https://domain/?v=2` or `og-image.png?v=2` (if you bump the meta URL).
3. Test in a chat that has **never** seen the old URL, or delete the previous message bubble.

### 5.4 Visual QA

- Tab icon is crisp at 1x and 2x, not a blurry 512 downscale in Safari (that is why 16/32 PNGs exist).
- iOS Add to Home Screen uses the 180px apple touch icon, not a screenshot of the page.
- OG banner: mark is centered, text is not clipped, no huge empty bands, no transparency showing as black.

### 5.5 Edge / regression

- `https://YOUR-DOMAIN` and `https://YOUR-DOMAIN/` (trailing slash) both unfurl.
- `www` vs apex: pick one canonical host and 301 the other. Mixed hosts fragment OG cache.
- Preview on a **page other than `/`** if you added `pageMeta` — confirm the image did not disappear.

## 6. Common failures and the exact fix

| Symptom | Cause | Fix |
|---|---|---|
| WhatsApp shows title/description, **no image** | Relative `og:image`, or image not publicly reachable | Set `metadataBase`, use absolute HTTPS PNG, confirm `curl -I` 200 |
| WhatsApp shows a **tiny square** (the logo) | You pointed `og:image` at the favicon / 512 icon, or used `twitter:card=summary` | Use 1200×630 `og-image.png` + `summary_large_image` |
| WhatsApp shows **old** image after you replaced the file | Scraper cache | Facebook Debugger “Scrape Again”; version the image URL |
| Image is a **black rectangle** | Transparent PNG used as OG, or dark mark on dark canvas | Opaque `#06080F` (or brand) canvas in the generator |
| Image is **cropped** / face cut off | Wrong aspect (e.g. 1080×1080 or 1920×1080) | Exact 1200×630; keep content inside a ~1080×560 safe rect |
| LinkedIn works, WhatsApp does not | WhatsApp wants PNG + Facebook cache; LinkedIn is more forgiving | Force `og:image` to PNG; scrape FB debugger |
| Local `next dev` preview looks fine, production empty | `metadataBase` still localhost, or image not committed / not deployed | Production origin only; commit `public/og-image.png` |
| `/favicon.ico` 404 | File not in `public/` or rewritten away | `public/favicon.ico` must be at the site root |
| Safari ignores SVG/WebP icon | Safari still likes ICO + PNG apple touch | Keep `favicon.ico` + `apple-touch-icon.png` |
| `sharp` install fails on Bun | Native addon blocked | Add `"sharp"` to `trustedDependencies` and reinstall |
| `icon.tsx` build fails | `public/icon-32x32.png` missing at build | Run `bun run favicons` before `next build` |
| Satori `ImageResponse` is blank | Used Tailwind classes / grid / remote font without loading it | Inline flex styles only |
| Bots get a challenge page | Cloudflare Bot Fight / Vercel Deployment Protection | Allow `facebookexternalhit` and `WhatsApp`; do not password-protect prod |

## 10. What “done” looks like

A third party pastes `https://your-domain.tld` into WhatsApp and sees:

1. A wide thumbnail that is the 1200×630 banner (logo + name + subtitle), not the tiny favicon.
2. The same title and description as `metadata.openGraph`.
3. The browser tab showing the mark from `favicon.ico` / 32×32 PNG.
4. No console 404s for `/favicon.ico`, `/apple-touch-icon.png`, or `/og-image.png`.

That is the implementation in this codebase. Reproduce those four outcomes and the port is complete.
